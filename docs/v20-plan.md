**(A) `msa.mjs` 的残基截断**（v19 发现、当时明确"未修"）与 **(D) `svgpng.mjs` 的 `<tspan>` 多行文本**

## 1. A：渐进比对丢尾部残基

### 症状（可复现）

```js
progressiveAlign([{id:'a',sequence:'ACGTACGTACG'},{id:'b',sequence:'ACGTACGTAC'}])
// v19: columns 10  →  a: 'ACGTACGTAC'（11 个碱基只留下 10 个，最后一个 G 消失）
```

11 bp 对 10 bp：**长的那条被静默截断**。v19 只在建树工具里加了覆盖度 WARNING 点名这件事
（`u2 (10 of 11 bases kept)`），比对器本身没动。

### 根因（不是"忘了补"，是补错了位置）

半全局（末端缺口免费）的 DP **允许**最优路径在任一序列末尾之前停下。实测该对的 DP 端点：

```
la 11 lb 10 endpoint { bi: 10, bj: 10 } best 40
last row  (i=la): 0 -4 2 12 6 12 18 28 22 28 34
last col  (j=lb): 0 -2 8 2 8 14 24 18 24 30 40 34
```

`H[10][10] = 40`，而 `H[11][10] = 34`、`H[10][10]` 所在的角点之外更差——**"丢掉最后一个 G"
确实是分数最优的选择**。所以这不是评分错误。

真正的问题是**补缺口的两个循环只覆盖了路径起点之前**：

```js
while (i > 0) { opA.push(columnString(profileA.rows, i - 1)); opB.push('-'.repeat(wb)); i--; }  // 前导悬垂：有
while (j > 0) { ... }                                                                          // 前导悬垂：有
// 端点之后的残基（suffix）：从来没有代码把它发出来
```

顺带一个**推理**：循环条件写作 `while (i > 0)` 而不是 `while (i > 0 && j > 0)`，
所以"路径必然到达边界"被当成了隐含前提。这个前提对**前导**悬垂是成立的（否则可以把路径
免费延伸到边界、拿到不更差的分数），对**尾部**悬垂则完全不适用——尾部残基就是被那个前提
"证明掉"的。测试因此**直接断言不变式**，而不是断言某个列数。

### 修法

把端点之后的残基作为**纯悬垂列**追加：

```js
const suffixA = []; const suffixB = [];
for (let k = bi; k < la; k++) { suffixA.push(columnString(profileA.rows, k)); suffixB.push('-'.repeat(wb)); }
for (let k = bj; k < lb; k++) { suffixA.push('-'.repeat(wa)); suffixB.push(columnString(profileB.rows, k)); }
opA.reverse(); opB.reverse();
opA.push(...suffixA); opB.push(...suffixB);
```

三个必须写对的细节：

1. **单独收集、不要 push 进 `opA`/`opB`**：那两个数组在 `reverse()` 之前是**反序**的，把正序的
   suffix 直接 push 进去、再整体 reverse，会把残基挪到**开头**（第一版实测输出 `GACGTACGTAC`，
   最后一个碱基跑到最前面）。
2. **`bi`/`bj` 是"路径已消耗的长度"**，所以 suffix 是 `[bi, la)` / `[bj, lb)`，与 traceback
   里用 `column index = i - 1` 的约定一致。
3. **`score` 不动**：悬垂列计 0 分，与被它替换的末端缺口同分，所以报告的仍是 DP 最优值。

### 不变式与测试

- **不变式**：每条输出行去掉 `-` 之后**逐字符等于它的输入序列**（顺序也算），且所有行等长。
- `test/smoke.mjs` 对多组不等长输入逐条断言该不变式（11/10、12/10、不等长多序列、
  无重叠的 4/4、前导悬垂、5/10 单侧完全悬垂）。
- **`coverageShortfall` 抽到 `phylo.mjs` 并导出**：v19 的 WARNING 现在**不该再对真实输出触发**，
  但守卫本身留着抓未来回归。测试**用一个故意截断的行驱动它**，断言仍报
  `u2 (10 of 11 bases kept)`——否则"没有警告"什么也证明不了。
- **行为变化**：v15 起、存在悬垂的比对输出列数会变（变多）。等长输入完全不变。
  `smoke.mjs` 里唯一钉住旧行为的断言（`alignment_columns === 10`，注释写着"比对着会 pad 而不是
  插 gap"）钉的**正是这个 bug**，已改为 11，并新增"覆盖度警告必须不再出现"。

## 2. D：`<tspan>` 多行文本（长叶名不再互相压）

### 症状

矩形树图里长叶名（如 `Escherichia_coli_K12_MG1655_chromosome_isolate_one`）被画成一行，
**直接压到相邻标签上**——图有内容但读不出来。v19 的 `svgpng.mjs` 把 `<text>` 里的任何嵌套标签
当作"这一段文本结束"，`<tspan>` 因此落进 `unsupported`，**同一段文字被画两遍**。

### 修法：分三层

**(1) 光栅化器支持 `<tspan>`（`svgpng.mjs`）**

- `<text>` 成为唯一支持嵌套的元素，产出 `runs`：每个 `<tspan>` 一个
  `{text, attributes, x, y}`。
- `x`/`y` 绝对定位与 `dx`/`dy` 相对偏移都支持（`dy` 是折行的机制）；
  空的自闭合 `<tspan dy="14"/>` 也推进基线 = 一个空行。
- **诚实边界**：`<tspan>` 带 `transform`、`<tspan>` 内再嵌 `<tspan>` → 计入 `unsupported`，
  绝不猜一个位置画出来。测试同时钉住"报告了"和"没误画"。
- **一个真 bug（实现时抓到）**：`</tspan>` 之后没有推进 `contentStart`，于是下一次 flush 从
  标签**内部**开始切片，把字面量 `"</tspan>"` 当成下一段文本画出来。表现是标签上叠了一层乱码。

**(2) 字宽度量抽成 `font-metrics.mjs`（新模块）**

排版要预留宽度、光栅化要画字形，**必须是同一个数**。复制一份常量会静默漂移（预留用 A 的度量、
绘制用 B 的度量，症状只是"标签压到邻居上"）。该模块只含几何常量与两个纯函数，
因此宿主侧两边都能 import，而 `svgpng.mjs`（import `node:zlib`）**永远不能进浏览器半**。

**(3) 折行助手进 `svgio.mjs`，替换手写估算**

- `wrapTextLines(text, maxWidth, size)`：按**真实字宽**折行，返回
  `{lines, width, height, step}`——调用方（树图）必须知道标签块占多高。
- `textSpanLines({x, y, lines, …})`：每行一个 `<tspan>`。
- 长标识符在**分隔符之后**断行（`_`、`-`、`.`、`|`、`:`）：把
  `Escherichia_coli_K12_MG1655_chromosome_complete` 从词中间劈开读起来像数据损坏，
  按 `_` 断行读起来像"换行的名字"。没有分隔符时按字数硬断，**绝不溢出预算**。
- 折行**无损**：断点只吃掉空白。

### 树图矩形布局

- 标签列宽 = 面板宽度的 40%（下限 90 px）；叶名按该宽度折成多行。
- **字号只在必要时缩小**（下限 5 px）：把标签缩到读不了比折行更糟。收敛条件是
  "每叶一行的行距必须放得下最高的标签块"。
- 折行**只在超宽时发生**，短标签是单行。**但几何与 v19 并非逐字节相同**：v19 用
  `字数 × 字号 × 0.62`（每字符 6.82 px @11）预留，现在用真实字宽（6.6 px @11），
  所以预留列略宽、分支尖端左移几像素。这是把估算换成真值，不是回归。
- **环形与扇形布局不折行**：旋转文本没有按真实字宽测量，硬折会算错行数；
  两者本来就在面板宽度外画标签。

### 图像回归守卫（关键）

`test/svgpng.mjs` 新增的树图断言**扫描像素**而不是断言文本：在标签列里统计"密集行"，
断言每个长名字**至少两行**、且 4 个标签块之间**至少留出 3 处空白间隔**。
v19 的单行长标签会把这个间隔数压到 0 或 1（也就是"压在一起"）——所以这条断言
**真的会因为那个 bug 而失败**。守卫的扫描区间从文档里**读出**（第一个 `<tspan>` 的 `x`），
因为靠猜会把分支尖端、支持度和标题都算成"标签行"（第一版就是这样，数出 9~10 条带）。

## 3. 顺带修掉：`preset.yml` 的工具数停在 52（v19 漏改）

v19 把工具从 52 加到 57：README、组合注释、工具表都改了，**唯独预设选择器里那行描述
还写着 "52 个 molbio_* 工具"**——用户在整个 v19 周期看到的是错的数字，而没有任何检查会发现它
（`preset-health` 当时只校验行的可挂载性与逐行结构漂移）。

- 描述改为 57 并补上 v19/v20 的新能力说明。
- **补守卫**：`preset-health.mjs` 的 `toolCountDrift(description, registered)`（导出给
  `drift-probe.mjs` 驱动）把描述里声明的工具数与**插件真正注册的数量**对比。
  解析刻意窄：`<n> 个 molbio_*` 与英文 `<n> tools`，因此 `90+ 限制酶`、`2–50 条序列`
  这类其它数字不会被误当成工具数；没有工具数描述的文案**不被逼迫**加一个。
- `drift-probe.mjs` 新增三条：描述正确时零噪音、v19 那种 52 vs 57 **必须被抓到**、
  无描述时安静。

## 实现后的偏差

1. **A 的第一版补错了位置**：按"补前导悬垂"的思路写了 `if (i > 0) / if (j > 0)` 两个补丁，
   实测**完全没生效**——因为 traceback 的 while 循环条件已经把前导悬垂耗尽，两个分支是死代码，
   而真正丢的是**尾部**。计划里"补缺口"的说法在实现时才被拆成"前导（已有）vs 尾部（缺）"。
2. **A 的第二版顺序错了**：把正序 suffix 直接 push 进反序的 `opA`/`opB`，输出成了
   `GACGTACGTAC`（末位残基跑到首位）。改成单独收集后再 append。
3. **D 的折行第一版有两处 bug**：长标识符里的 `_` 让分词器把每个 `_` 之间当成一个"词"，
   于是 `A` 单独占一行；以及"整段就是一个长 token"时会丢掉第一段（`current` 被覆盖）。
   都补了针对性测试（`wrapText` 无损性与"不溢出预算"）。
4. **D 的解析器漏了 `contentStart`**（见上），表现是标签上叠一层 `</tspan>` 字面量。
   这个 bug 是**看图**发现的——`svgpng --preview` 之外，直接用 harness 的 `read_image`
   把渲染结果读回来看，正是 v18 建立的那条人眼复核链路。
5. **树的短标签几何有微小变化**（估算 → 真实字宽），计划时以为"短标签完全不变"，
   实测分支尖端左移几像素。已在 CHANGELOG 里写明，没有假装逐字节相同。
